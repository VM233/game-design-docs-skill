# 整理示例

以下均为虚构材料，用于说明信息取舍；其中的规则、数值与选择不属于任何实际游戏。

## 从过程记录提炼当前设计

原材料：

> 周一先做工作台制作。周二用户说“基础制作放在背包，点击立即制作，取消工作台和等待队列”。周三改了按钮。周四修满背包扣料失败，case17通过。周五又跑了38项测试，截图在测试目录。之后准备补种植，但用户还没确认。

整理后可以放在同一主题中：

> **基础制作**：玩家在背包点击配方立即制作，不使用工作台或等待队列。来源：周二用户变更要求，关联会话消息。旧工作台方案已被此要求替代。
>
> **选型理由**：在该项目中选择背包即时制作，使玩家探索时可直接补充基础工具，省去返回工作台和等待的操作成本；代价是基础制作不承担设施规划或时间管理。后续如果用户需要设施成长，再重新评估。
>
> **库存边界**：扣除材料与放入产物应同时成功或同时失败，容纳计算包含本次消耗腾出的空间。配置及实现见现有配方和库存交易入口。
>
> **已知问题**：满包时先扣材料、后检查产物空间可能损失材料。已改为先验证完整交换后提交；该复现场景已通过，证据链接指向原报告。其他场景不因这一用例通过而自动通过。
>
> 种植用途仍未获确认，不写入当前设计目标。

选型理由只有在材料支持上述因果时才作为已作出的决策保留；否则写成当前建议及其依据。没有可靠来源时不能把示例里的“周二”补成具体日期或伪造会话链接。按钮修改过程和测试次数不进入设计正文。

## 明确变更与需要决定的冲突

| 已知信息 | 如何维护 |
| --- | --- |
| 用户原来要求自动装备，现在明确说“取消自动装备，拾取后放背包” | 直接更新该行为及相关交互描述；不再询问是否真的取消。其他不冲突的快捷栏要求继续有效 |
| 用户原来要求道具不损毁，现在要求“失败惩罚再强一点” | 不能自行推成死亡摧毁装备；保留不损毁约束，在其内提出惩罚方案。只有确需突破该约束时再询问 |
| 用户要求所有建筑自由放置，同时明确保留道路必须沿可通行地面的限制 | 记录自由放置及道路例外，避免用一条笼统规则覆盖具体范围 |
| 用户要求某模式离线运行，又要求其交易必须实时接入在线市场，但未说明离线交易如何处理 | 明确离线状态下两项要求的冲突，请用户决定离线禁用交易、恢复联网后结算等行为；继续整理非交易玩法 |
| 较新的测试报告仍验证旧解锁系统，用户已经明确取消解锁 | 报告只能证明当时构建的测试结果；当前设计移除解锁，将相关实现或验证差距如实列出 |

不要把每种情况都变成审批步骤。已经明确的变更直接同步，只有缺少必要产品决定才询问。

## 用可验证的理由解释选型

薄弱表述：

> 使用分区保存，架构更先进，性能更好。

有用表述：

> 选择按区域保存，因为玩家通常只修改附近少量区域；整世界重写会把远处未修改数据计入每次保存。代价是需要区域身份及跨区域一致性规则。是否能达到目标设备的保存延迟尚未测量；若世界变成固定小关卡，应重新比较整关保存的复杂度。

这表达了选择逻辑与未证实部分，不假装已经完成性能对比。若本次只是很小的显示文案调整，无需为它凑一张选型表。

## 一个问题，一个可读结论

原材料：

> 第1轮水面亮条失败，第2轮减粒子，第3轮调透明度，第4轮拓扑48项通过，第5轮仍像白帘，之后又拍了侧面；可能是粒子问题，也可能是水面。

整理为：

> **瀑布主体呈连续白帘**：正面和侧面都遮住落点，用户否定这一外观，关键反例见指定图与动态片段。减少粒子和调透明度没有消除问题。原因尚未确认，需区分连续水体光学与离水粒子的贡献；拓扑48项通过仅证明对应连接规则。当前外观仍未通过，下一次应在相同视角复核主体轮廓与落点可读性。

不要把“可能由粒子导致”改成已证实根因，也不要因技术测试通过删除用户反例。若另有“岸线露缝”，应作为独立问题；二者没有已证实的共同机制时不要合并关闭。

## 根据主题选择篇幅

小型玩法调整可以一篇写目标、原因、规则和未决问题。大型项目可以让物品系统、世界生成和战斗各自有独立设计，再由轻量入口连接。研究日志有新结论时，修改主题的当前判断，并用少量来源支撑；不要把每次检索结果追加为一节。

删减的验收标准是：后来的人仍能找到当前要求、理解取舍、复现关键问题、知道验证边界。减少字数或文件数量本身不等于整理成功。
